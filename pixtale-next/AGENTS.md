# 项目概览

一个基于 Web 的照片图库应用。

# 注释规范

- 每个方法都必须写上注释，说明其用途。
- 在后端文件中，紧跟在 `import` 语句之后添加模块说明，并空一行分隔。
- 为复杂的逻辑代码块添加行内注释。

# 通用编码规范

- 变量名和组件名应简洁且具有表达力。避免名称过长、过度抽象、过度工程化，或添加使代码变得臃肿的不必要防御性检查。

# 后端规范

- 遵循 MVC 架构。为所有 Service 方法明确指定返回类型。
- 如有需要，在 API 层从 `context.js` 获取当前用户 ID，并将其作为最后一个参数传递给 Service 层。
- 将输入参数类型放在 `entity/bo` 中，将返回值/响应类型放在 `entity/vo` 中。

# 前端规范

- 导入并复用后端定义的 API 请求和响应类型。
- 避免不必要的组件抽象，仅在确实需要时提取组件。
- 在组件内部说明每个 state、ref 以及关键变量的用途。

# 数据库位置

`data/pixtale.sqlite`
